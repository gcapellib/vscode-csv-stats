# Changelog

Newest first.

## 0.30.3

- **Fixed:** a Windows-1252 file (what Excel writes) showed `€`, curly quotes and the long dash
  as invisible control characters on Node versions that decode it as ISO-8859-1 (Node 20, the one
  the CI uses). Those 32 signs are now read from a table, whatever the Node version.

## 0.30.2

- **Docs:** the first screenshot is the Prism duo palette again, redone with the current
  version. The package no longer carries `scripts/` and `.claude/`.

## 0.30.1

- **Fixed:** the `pd.read_csv` in *Dataset…* now carries `encoding="cp1252"` (or `"utf-16"`)
  when the file was not UTF-8; without it pandas misread the accents of a file the plug-in
  had read correctly.
- **Docs:** the README, the guide and the extension's description now cover the cleaning steps
  and the files that open (tab, `|`, Windows-1252, UTF-16); the description puts cleaning
  ahead of palettes.

## 0.30.0

- **Replace text inside cells.** *Replace text…* finds a piece of text in each cell (`€`, `kg`)
  or a regular expression written `/like this/` (`$1` for a group). *Replace values…* still
  needs the whole cell.
- **Fill up, and fill empty cells with a value.** Beside *Fill down*, in the column menu.
- **Remove the rows shown.** With a filter on, *Remove these N rows* takes them out of the
  cleaned table (outliers, one value, a spelling…) as a step, removable like the others, with
  its pandas line.
- **More files open as they should.** Tab and `|` separators; Windows-1252 and UTF-16 files
  are decoded instead of showing `�`. The copy you save stays UTF-8.
- **The field you type in unfolds beside the menu** you clicked, instead of VS Code's box at
  the top of the window. Enter confirms, Escape cancels, a bad regular expression or a bad
  number of decimals is refused in place, and clicking the same entry again closes it.
- **Menus and panels unroll** in 130 ms (not with reduced motion).
- **Instant tooltips everywhere.** The plug-in's own tooltip replaces VS Code's slow one on
  every button, row and cell.
- **Headers in colour.** *Dusk* and *Woodland* draw each column name in its column's colour,
  adjusted to a 4.5:1 contrast against the header; about half of the *Random palette* draws
  do too.
- **Docs:** new screenshots, and a GIF of random palettes. `npm run screenshots` makes them again.

## 0.29.4

- **A placeholder that dominates is caught.** With 25 of 30 values at `-999` the quartiles
  were the placeholder's own and nothing stood out; the known placeholders are now judged
  against what is left once they are set aside.
- **Placeholders written with spaces** (`-999 `) are found by *Show the rows* too.
- **The same count everywhere.** The column menu and *Clean* count similar spellings over
  the whole file; *Clean* used to count only the rows left by an active filter.
- **Light theme, shipped palettes.** The gold and orange inks of *Dusk*, *Fjord* and
  *Bordeaux & gold* turned brown or olive on a light background. Their light versions are
  now built like the draws: a tone-on-tone gradient moves as a block into the readable
  range, and distinct colours fold their orange, yellow and yellow-green to coral and green.
- **Average by category** ignores a non-finite value instead of letting it spoil the
  whole table.
- **Tests:** nine integration tests cover the column menu, *Clean*, the placeholders, the
  row-order curve, the average by category, the gaps, the garbled characters and the
  palettes without grid lines, on a small file that holds each defect once
  (`tests/fixtures/dirty.csv`). `npm run lint` now covers the tests and the scripts.
- **Removed:** `applySort`, the unused broom icon, and five unused CSS classes.

## 0.29.2

## 0.25.0

**Cleaning, with the original kept intact.** What changes the data is now a
*step*, replayed on the file as it was read — which is never modified:

- **A broom on every column header**, next to filter and sort (right-clicking
  the header opens the same menu): trim spaces, clean invisible characters,
  lowercase / UPPERCASE / Capitalize Each Word, replace values, treat tokens as
  empty, fill down, change type, rename, remove the column. Entries that make no
  sense for the column (trim on numbers) are not shown.
- **The Clean button** in the toolbar: the applied steps in order, each with
  what it touched (*20 cells*, *−3 rows*) and a cross to remove it — the list
  then replays without it; the full catalogue, including duplicate and blank
  rows; and **Save cleaned copy…**, which writes `name.clean.csv` next to the
  file, then `name.clean-2.csv`, never over the original or an earlier copy.
- **Changed cells are underlined** in their column's accent; hovering one tells
  what it was. A column with steps lights its broom.
- **pandas:** *Dataset…* replays the steps (`str.strip()`, `drop_duplicates()`,
  `to_numeric(errors="coerce")`…) and writes the copy with `to_csv`, before the
  filters and sort, which are only for looking.

Rename, remove and *read this column as* were view settings; they are steps now,
listed and undoable like the others. Changing the type empties the values that
do not read in it, as Power Query does, and says how many.

**Column details** moves to a chart button at the top right of each band, where
the `⋯` was. **Fixed:** a panel opened from a header button no longer covers that
button — it went up to fit on screen and swallowed the click meant to close it —
and a long menu now scrolls instead of running off screen.

## 0.24.3

(0.24.0 to 0.24.2 were trial builds of a cleaning panel, since withdrawn; this
version follows 0.23.11.)

**Unique values.** Each band gains a *Unique* line under *Distinct*: the values
that occur exactly once, what Power Query calls unique. In a list of categories
they are often typos the ranking hides under *Other*. Clicking the line keeps
only those rows, and the generated pandas reads
`df[df[col].notna() & ~df[col].duplicated(keep=False)]`. It replaces the note
*every value occurs once*, which is now simply *Unique* equal to *Distinct*.

**Dates and times.** A column whose every value reads as a date or a time gets
its own type — `date` or `time` — with a timeline instead of a ranking, *Min /
Max*, mean and median written as dates in the file's own convention, a
chronological sort, a *before / after / between* filter, and `parse_dates` (with
`dayfirst=True` when needed) in the generated `pd.read_csv`. Times alone become
durations with `pd.to_timedelta`. Recognised: `2015-01-31` and `2015/01/31`, with
or without a time; `31/01/2015`, `31.01.2015` and `31-01-2015` only when a day
above 12 settles the order; `12:52` and `12:52:01`. The American `01/31/2015` is
not read. *Read this column as* offers Date and Time too.

**Fixes.**
- A column no longer changes type under a filter. Keeping only the empty cells
  of a numeric column turned it into text, and its filter into a value list.
- *Read this column as* is recomputed on the filtered rows, like every other
  band, and is no longer lost at the next filter change or undone by a rename.
- Reopening a numeric filter shows *Only empty cells* or *Hide them* when one is
  active, instead of *Follow the condition*.

**Listing.** The description is shorter — what it does, the screenshots, what's
new — and the detailed explanations moved to `docs/guide.md` on GitHub.

## 0.23.0

One filter panel per column, whatever its type — same place, tabs that fit the
column.

- **Numbers**: one operator menu (`=`, `≠`, `>`, `≥`, `<`, `≤`, `between`) and
  one value (two for `between`), replacing From / To / Exactly.
- **Text**: *Values* (the checklist) and *Text* (contains, does not contain,
  starts with, ends with, is, is not; case-insensitive). The panel opens on
  *Text* when a column has more than 200 distinct values — ticking one value

- **Empty cells**: one choice instead of a checkbox and a button — follow the

  column named tel/phone/zip/postal…) are read as text, not as numbers. The
  "Read this column as" menu still overrides it.
- The column menu has a single "Filter…" entry.

**Column widths by hand.** Every width used to be fixed by the automatic
calculation. Drag the right edge of a header to resize a column, up to 1,600
pixels; double-click the edge to widen it until nothing is cut, past the
automatic width's own ceiling, and again to shrink it back.

With the insights band open, the default width is a floor: a column can be
widened but not squeezed below what its histogram and bounds need — shrinking
to the title alone crushed them. With the band folded, a column narrows freely
and the double-click shrinks it to its title, read in full beside its two
buttons; reopening the band brings it back to its default width.

**Percentages now read against every row, blanks included.** The value ranking
in the band and in Column details divided by filled values only. Column details
listed blanks on that same base, and so showed "(blank) 149.3 %"; the band
showed a column that is 93 % empty and otherwise "True" as "True 100 %" — right
about the filled values, misleading about the file. Shares are now taken over
all rows, as pandas' `value_counts(dropna=False, normalize=True)` does: blanks
take their rank as "(blank)", and the list adds up to 100 %. Checked against an
independent computation on a 3,042-row, 35-column file: no difference.

Clicking "(blank)" now keeps every cell the statistics count as missing,
whitespace-only ones included, and the pandas snippet finds them with `isna()`
— pandas reads an empty field as NaN, and the former `== ""` matched no row.

**Updates always take effect.** The view's script and style were addressed by
the same URL from one install to the next whenever the version number stayed
the same, and VS Code could keep serving an old cached copy even after
reloading the window — a feature installed and tested did nothing. Their URL
now carries the file's modification time.

**Empty cells can be filtered in every column.** Only text columns offered
"(blank)", in their value list; a numeric column — a phone number read as a
number, say — offered a range and no way to keep its empty cells. An empty cell
is a state, not a value of the column's type, and every spreadsheet filters it
the same way whatever the type. Click "Missing" in any band to keep the rows
where that column is empty; clicks on several columns add up, which answers
"how many listings have no contact at all". The numeric filter gains "Empty
cells only" and "Include empty cells", to keep a range *or* the empty cells —
translated for pandas, where NaN satisfies no comparison, as `between(...) |
isna()`.

**The band says which base each share uses.** "Missing" is a share of every
row, "Distinct" a share of filled values — the convention of pandas (`nunique()`
over `count`) and of ydata-profiling, checked in its source. Side by side, a
latitude 49 % empty and 99.7 % distinct looked contradictory; the line now reads
"Distinct 1,547 (99.7% of filled)", and column widths make room for it in bold.
"Missing 0" is greyed out: identical to a clickable "Missing", it invited clicks
that did nothing.

**Column index in the band.** Each band shows the column's position next to its
type — "TEXT · #3" — counted from 0 as pandas does. Dropping a column renumbers
the ones after it, as `df.drop` does, so the number is the one `df.iloc[:, 3]`
expects on the dataframe the Dataset snippet builds.

**All values right-aligned.** Only numbers were, after Excel, so a row
switched between left and right from one column to the next.

Checked with real mouse gestures in a real browser, which caught three bugs
before release: the double-click never registered, because the header is
rebuilt on every repaint and the edge under the cursor was replaced between
the two clicks; Chromium's pointer events carry no click count, so the gesture
moved to mouse events; and a gesture made while the fold animation ran was
overwritten by its next frame.

## 0.21.1

**Neighbouring columns never share a text colour.** On coloured backgrounds the
text took each column's hue in a deep shade, and when a gradient stayed within
one family those shades all looked alike: 49 % of neighbouring pairs had
identical text. The text now keeps its column's hue but alternates depth from
one column to the next — measured as perceived difference (OKLab), the median
gap between neighbouring texts goes from 0.006 to 0.142, and no pair is
identical any more. Draws whose coloured text cannot be told apart are
redrawn; the sunshine and citrus gradients no longer colour text, since their
yellows and limes, lightened or shifted to avoid mustard and olive, ended up
alike.

**More rainbows, after Prism and Prism duo.** About a third of the draws are
now full rainbows — six to eight hues at even steps around the wheel, random
start and direction, the last hue meeting the first at an ordinary step. As
coloured text they borrow Prism's or Syntax's style; as coloured backgrounds,
Prism duo's or Rainbow duo's — dark tinted cells with vivid text in dark mode.
A rainbow always has a yellow and an orange, whose dark cells would be brown:
they are desaturated to a dark neutral instead of lightened, so no column
jumps out, and the text carries the colour.

**The header band stays legible.** Histogram bars and ranking percentages are
drawn on the band, not the cell, and nothing checked them there: in palettes
blending a list style with a gradient, 74 % fell below the contrast threshold,
down to pale yellow on pale yellow. An accent too close to its band is now
redrawn in the same hue, dark or light enough to read, and the text written on
the band (Missing, Distinct, the ranking) is held to the same threshold.

## 0.21.0

**Random palette** only — the shipped palettes render byte for byte as before.

Draws were garish, brownish, and all alike: every column held the same
lightness while the hue jumped from one to the next. A draw now traces a
gradient — lightness and hue moving together, step by step — in one of six
shapes — including citrus and sunshine, for yellows, oranges and greens — and
the table walks it back and forth rather than jumping when the colours start
over. Background colours are drawn towards a muted mid-light tone, with text
in each column's own hue; coloured text spans a wider range so its gradient shows.
Brown, ochre, tan, taupe, terracotta, khaki, mustard, olive and burgundy are
kept out by a minimum lightness per hue rather than by rejection.

Half the draws blend a palette from the list with a random gradient: the list
palette keeps its style and takes the gradient's hues. Every palette in the
list takes part, except Okabe-Ito and Tol Bright, whose inks are given one by
one.

Measured over 200 draws (38,400 colours shown), 0.20.0 against 0.21.0:

| | 0.20.0 | 0.21.0 |
|---|---|---|
| Brown or olive colours | 2,452 | 0 |
| Lowest text/background contrast (threshold 60) | 66 | 71 |
| Path shapes, in both families | 1 | 6 |
